# 作业人员姿态识别安全监测系统

基于浏览器端人体姿态识别的作业现场安全监测系统。摄像头、本地视频、现场照片三种输入，实时识别**跌倒、弯腰作业、攀爬、人员滞留、进入危险区**，并通过语音播报 + 待处理告警队列形成「判定 → 事件入库 → 话术播报 → 人工确认」的闭环。

**所有推理都在浏览器本地完成**，画面不上传任何服务器——模型文件随项目一起静态托管，离线可用。

## 功能特性

- **三种输入源**：USB/内置摄像头实时采集、上传视频文件循环分析、上传现场照片做单帧检测（也支持拖拽到画面、`Ctrl+V` 粘贴截图）
- **五种行为判定**：跌倒 / 弯腰作业 / 攀爬作业 / 人员滞留 / 进入危险区，按危险等级分色（低 / 中 / 高）
- **多目标追踪**：同时跟踪最多 6 人，每人独立 ID、独立姿态分与事件冷却
- **手绘危险区**：在画面上点击绘制多边形区域，髋部落入即判定越界，停留超时升级为滞留
- **语音闭环**：Web Speech 本机合成播报，高危告警可连续播报、未处理自动重播
- **事件可追溯**：事件表按类型筛选、可导出 CSV、附带现场缩略图，历史会话按次存档
- **图片单帧检测**：骨骼叠加 + 标注图导出（原图分辨率合成）
- **零后端依赖**：纯静态站点，`index.html` 打开即用

## 快速开始

需要一个静态 HTTP 服务（浏览器要求 `localhost` 或 HTTPS 才能调用摄像头）：

```bash
# 方式一：项目自带脚本
python serve.py          # 默认 http://127.0.0.1:8123

# 方式二：任意静态服务器
python -m http.server 8123
```

Windows 下也可直接双击 `start.bat`。

然后浏览器打开 `http://127.0.0.1:8123/`，点击「启动摄像头」授权即可。

> 首次加载需下载姿态模型（约 3~15 秒），之后命中浏览器缓存。

## 使用流程

1. **启动摄像头** → 画面出现骨骼与目标框
2. **绘制危险区**（可选）→ 在画面上点若干顶点，点「完成区域」
3. 系统自动判定并在右侧产生统计与告警队列，左下角播报话术
4. 告警需在队列里「确认」或「忽略」，否则按设定间隔重播
5. 无摄像头时可用「上传视频」或「上传图片」验证判定效果

## 识别规则与可调参数

所有阈值在「系统设置 → 识别阈值」中调整，**拖动即生效**并保存在浏览器本地。默认值定义在 `assets/js/engine.js` 的 `DEFAULT_CONFIG`。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `fallAngle` | 62 | 躯干与竖直方向夹角超过该值视为跌倒候选 |
| `bendAngle` | 40 | 弯腰判定起始角度（与膝角共同判定） |
| `kneeStraight` | 150 | 膝关节伸直阈值，越大越要求腿伸直，避免深蹲误判 |
| `fallFrames` | 6 | 跌倒需连续满足的帧数，抑制瞬时误报 |
| `bendFrames` | 4 | 弯腰需连续满足的帧数 |
| `climbHold` | 1.2 | 双手举过头顶需保持的秒数 |
| `loiterSec` | 8 | 危险区内停留超过该秒数升级为滞留 |
| `confGate` | 0.65 | 低于该置信度的事件不写库、不播报 |
| `eventCooldown` | 10 | 同一目标同一事件的最小记录间隔（秒） |
| `maxPersons` | 6 | 同时检测的最大人数（改动需重启采集） |
| `maxFps` | 24 | 处理帧率上限 |
| `modelQuality` | lite | `lite` 快 / `full` 准（改动需重启采集） |

判定逻辑：

- **跌倒**：躯干倾角 ≥ `fallAngle`、包围框横置（宽高比 ≥ 1.2）、髋部 0.8s 内骤降，三项加权评分 ≥ 0.6 后累计 `fallFrames` 帧
- **弯腰**：倾角落在 `bendAngle` ~ `fallAngle-4` 区间且膝关节伸直，持续 `bendFrames` 帧
- **攀爬**：双手高过鼻尖并保持 `climbHold` 秒
- **进入危险区 / 滞留**：髋部中点落在多边形内；停留 ≥ `loiterSec` 升级为滞留
- 新轨迹需稳定 5 帧后才参与动作判定，避免 ID 抖动误报

## 目录结构

```
.
├── index.html              # 单页应用（统计面板 / 舞台 / 告警 / 设置）
├── serve.py                # 本地静态服务（含 COOP/COEP 头）
├── start.bat               # Windows 一键启动
└── assets
    ├── css/style.css       # 全部样式
    ├── js
    │   ├── app.js          # 主程序：采集循环、绘制、交互、图片检测
    │   ├── engine.js       # 姿态引擎封装、多目标追踪、行为判定规则
    │   ├── alerts.js       # 告警中心（队列 / 确认 / 重播）
    │   ├── voice.js        # Web Speech 播报与话术
    │   └── store.js        # 配置与历史会话本地存储
    ├── models              # MediaPipe Pose Landmarker（lite / full）
    └── vision              # MediaPipe Tasks Vision 运行时与 WASM
```

## 技术栈

- 纯前端：原生 ES Module，无构建步骤、无 npm 依赖
- 姿态识别：[MediaPipe Tasks Vision](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker) — Pose Landmarker（33 关键点，lite / full 双模型）
- 追踪：自研 IoU + 中心距匹配，带迟滞确认
- 判定：几何规则（躯干倾角、关节角、包围框形状、髋部高度变化）
- 播报：Web Speech API（本机合成，无需联网）

浏览器要求：Chrome / Edge 90+（需 WebGL2、WebAssembly SIMD）。Safari 与移动端可跑但帧率较低。

## 说明

- 模型与 WASM 运行时合计约 34MB，已随仓库提交，克隆即可离线运行
- 判定基于 2D 关键点的几何规则，属于**辅助提醒**，不能替代现场安全管理；画面中人物过小、被遮挡或大面积逆光时准确率会明显下降
- 危险区为运行时手绘数据，保存在浏览器本地，不随代码分发
